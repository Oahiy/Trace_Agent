## 4. 自动检查与语义复核

自动检查分别验证：

1. 问题、文档范围、年份与固定题目一致，顶层条件原样保存。
2. 文档真实 READY，索引版本一致，排除原因确实由发表年份导出；未就绪空集不能冒充年份过滤成功。
3. 检索片段与数据库采集的原文、来源、定位和元数据一致。
4. 结果保留证据快照、实际条件、排除原因、版本与限制。
5. 上下文装入/遗漏吻合，引用来自实际装入的片段。
6. claim 与 support_fragment 一致且逐字来自原文；引用元数据由服务端提供。
7. 拒答无 claims；过滤空集零生成、零查询 Embedding；技术失败使用固定安全错误。
8. 调用量不超原上限，测量耗时为合法有限值。

通过后答案仍为 pending_review。实际出现了“原文和页码正确、回答却无关”的反例，所以必须独立检查相关性、完整性、条件保留和冲突处理。

复核绑定题目与完整观察的哈希，涵盖请求、证据、结果、用量及测量记录。`review` 从观察重新计算自动检查，不相信缓存中的绿色分数，再校验复核覆盖和哈希。回答的相关性、完整性、条件保留都要明确判断；不适用的冲突项可记 not_applicable。

reviewer=agent 仅代表代理意见，全部 developer_review 仍 pending。哈希检测漂移，不是数字签名，不抵御有写权限者同时改报告和复核文件。不能自动改哈希冒充重新复核。

- 限定单来源时来源命中容易高分，必须另查正确证据、相关性与完整性；锚点也不等于语义支持。
- 没有 claim 的题不填支持率 100%，未知 Token 不填 0；保留估算、供应商实际统计与扣费用量的区别。
- 六题生成四次、查询 Embedding 四次；额外四类临床拒答零推理。小样本不报告有统计意义的 p95 或总体可靠率。

## 6. 安全修复与失败行为

根因：原 guard 正则的点号不跨换行，PDF 常在单词间换行。合成来源中 Ignore 后换行的忽略指令可被旧绑定逻辑发布。先加六个回归用例，旧实现实际为 3 failed、3 passed；修复后六个均通过。

修复只对安全比较视图执行 NFKC、casefold、合并空白。数据库原文、摘录、字符定位和文件哈希不改变；测试验证普通跨行摘录仍逐字保留。工作流升为 med-extractive-v3，使安全行为可追踪。

这不是完整注入防御：关键词仍可能漏判、误拒，dev-10 的可用性差距也保留。来源是不可信数据，服务端权限、受限选择和最终绑定分别承担不同防线。

旧终态任务仍按原幂等键查询/复用，不能冒充新模型重跑。未执行的旧版本研究任务按已有版本检查安全失败；使用新幂等键前核对真实状态，不能覆盖或盲重试。本次应用库没有研究任务，前后快照一致。

| 情况 | 行为 |
|---|---|
| 空集、证据不足、医学越界 | SUCCEEDED/refused，claims=[]；空集与预判医学请求零推理 |
| 模型故障、无效输出、预算不足 | FAILED、result=null、安全错误；失败请求仍保留计数 |
| 输入损坏、旧复核、观察缺失 | 命令非零退出，固定错误，不输出原始异常 |
| 采集完成但质量失败或待复核 | 普通命令返回 0；--require-quality 返回 2，保留逐题结果 |
| 报告写入失败 | 返回 1 和 report_write_failed，不声称已经保存 |
| 重放终态任务 | 同 job、零新增推理，标记 reused_execution |

首次真实编排另发现脚本错误地从 IndexTask.document_id 取预算，该表实际通过 job_id 关联。修为经 Job 联表并带 owner 条件，新增真实 PostgreSQL 回归检查本人可读与他人不可读，再重跑；没有重置已有索引预算。

## 10. 如果由你独立开发

先手写一题的输入、期望、证据位置和拒答/失败分支，让 AI 实现小切片，自己确认后再扩六题。不要先接受 AI 实现，再照实现写同义断言。

你必须掌握：

1. **需求**：有引用、相关、完整是不同要求；安全性和允许任务完成也分别评分。
2. **身份与日期**：source_id、document/chunk UUID、文件哈希、索引版本、快照各司其职；物理页、版本年份和发表年份不同。
3. **Python 设计**：纯函数适合固定输入测试；脚本编排 I/O；外部边界异常只给固定安全码。
4. **后端状态**：SUCCEEDED/refused 与 FAILED 不混用；重复请求复用任务，重放不算新实验；模型等待不持有事务。
5. **测试**：主动改页码、年份、上下文和 owner，制造注入与超时；索引外键错误需要真实数据库验证，纯替身发现不了全部问题。
6. **RAG 排查**：资料→READY/过滤→检索→上下文→选句→绑定→保存→评分。dev-01 已命中锚点，盲换 Embedding 未必解决；dev-03 先补检索；dev-05 还受上下文与单摘录限制。
7. **评价诚实**：固定预期、保留失败；字面锚点不是语义判断，全部拒答没有应答高分，代理意见不是本人验收。
8. **交付**：记录实际版本、用量、退出码、执行顺序；缓存统一管理，凭据随卷保留，只提交本次文件并检查 staged diff。
