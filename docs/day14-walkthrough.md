## 4. 实验如何完成

1. 先检查仓库、未提交修改和锁定环境。用户原有 AGENTS.md 修改不进入本次提交。
2. 复用唯一缓存清单，添加 day14 项与明确忽略路径，再开始产生本日文件。
3. 启动已有 Colima、PostgreSQL、Redis，保存原应用数据库一致性摘要及 33 个受保护文件指纹。只使用 traceagent_test 与 Redis DB 1 运行测试/演示。
4. 先执行新单元检查、新真实数据库检查和完整既有测试，再运行真实六题，以保留最后的隔离演示状态。基础检查关闭真实服务开关，可以与真实数据库测试独立执行；两份真实数据库测试/演示不得并行。
5. 实际上传三份锁定 PDF，经独立 worker 得到 43/74/59 个片段，并通过既有索引服务进入 READY。全部六题重新执行，旧幂等结果不冒充新结果。
6. 固定候选配置后运行检索对照。三道非空范围题各调用一次实际查询 Embedding；每题的 A/B 两组复用同一个向量。dev-08 在范围为空时零调用。实验共 **3 次 Embedding、0 次生成**。
7. 核对目标 PDF 页与已存片段、完整兼容向量范围，验证实验向量路径的前五等于生产仓库返回的前五，再比较候选。
8. 对实际六题输出重新做代理原页复核，绑定本次观察哈希。不是复制旧哈希取得通过。
9. 执行严格门禁、真实实验重放拒绝、数据保留核对，记录负面结果和剩余问题。原应用与 33 个受保护文件保持。

## 5. 候选配置与结果

| 固定项 | 值 |
|---|---|
| 基线 | 原有余弦距离精确排序 |
| 词法路径 | PostgreSQL english 配置、ts_rank_cd |
| 查询规则 | 从问题提取 ASCII 字母/数字词，去重后 OR；数据库继续做词干化和停用词处理 |
| 路径候选上限 | 各 20 个 |
| 融合 | 等权 RRF，常数 60 |
| 最终返回 | 5 个，与原契约一致 |
| 同分 | 固定文档、片段 ordinal、片段 ID 顺序所形成的稳定顺序 |
| 检索诊断上限 | 每题 2 次 Embedding，整个实验持久上限 6 次；不允许生成 |
| 诊断最大范围 | 2048 片段，超限明确失败而非静默截断 |

RRF 对片段的得分是各路径 `1 / (60 + rank)` 的和，缺席路径贡献 0。不同路的原始分数尺度不同，不能直接相加；原有 distance 的余弦距离含义也不能暗中换成融合分数。本实验没有修改生产返回字段。

|---|---|---|---|
| dev-01 | 两个锚点均 1 | 2、1 | 两个锚点均保留并装载 |

dev-01 词法独立路径的前五虽然包含两个锚点，预算装载后并没有同时保留两个。这再次说明“前五命中”和“实际可供模型使用”必须分开计算。该词法独立路径只是诊断记录，不是第二个调参候选。

原始 PDF 锚点、保存片段锚点均核对通过。锚点指标要求指定来源、物理页码与标准化文本同时匹配；它是固定位置诊断，不是通用语义评分。其他页如有等价证据应由语义复核判断，不能仅凭锚点未命中就宣称任意答案必错。本次实际回答仍为第 1 页条目制定背景，确实没有回答注册信息。

单次诊断中向量 SQL 约 1.6–2.9 ms、词法 SQL 约 7.5–10.3 ms；查询顺序、缓存状态、全范围诊断和额外基线核验均影响耗时，不能当生产 P95 或扩展性结论。候选没有新增生成调用，但增加数据库工作。

## 6. 后端设计和失败行为

本次主要代码位于 scripts/day14.py。没有把医学题号、标准答案、关键词或页码写入 TraceAgent 平台层。

- **权限先于排名。** 两路都执行 active owner、document scope、READY、索引/摄取版本和发表年份条件。不能先在全库取前五再过滤，否则既影响召回也可能泄露其他用户资料。
- **事务不跨模型等待。** 在短 session 中检查范围，关闭 session 后等待 Embedding，再新开 session 重查快照后执行查询。避免外部服务等待占用业务事务和连接。
- **先预留再请求。** QueryBudget 在请求前更新共享次数并原子保存。失败和重试也计入，持久写失败会阻止模型请求。新建每题预算不会刷新全局六次上限。
- **并发与重放。** 非阻塞文件锁阻止同时运行；已有 experiment.json 时拒绝重新实验。真实重放退出 1，原账本哈希不变。中断可能保留 collecting 状态和已占次数；不删除文件重置配额。
- **原子、安全报告。** 复用既有临时文件、fsync 和同目录替换；文件私有，拒绝路径穿越、符号链接和非白名单目录。本次只把 day14 加入显式白名单。
- **零匹配不等于故障。** 词法零匹配时融合保持向量排序；数据库失败不能吞掉后冒充空结果。未知异常只输出固定安全码，不输出原始异常或 SQL。
- **状态语义。** 年份条件排空属于业务拒答，可为 SUCCEEDED/refused；模型/数据库/预算故障走失败契约。完成采集与质量通过也不同：review --require-quality 本次退出 2。

本实验英文 ASCII 查询处理范围有限，没有完整多语种方案。ts_rank_cd 是 PostgreSQL 全文排名，不是 BM25。关键词防护、提示词和原文绑定都不构成全面语义/注入保证。

## 9. 当前方案核对

核对日期 2026-10-23。本地 Python 3.12.14、FastAPI 0.141.1、SQLAlchemy 2.1.4、pgvector Python 0.5.0；实际数据库 PostgreSQL 18.6、扩展 0.8.7；实际模型服务 Ollama 0.40.2。qwen3:1.7b 与 nomic-embed-text:v1.5 digest 按既有适配器核验，768 维、任务前缀与模型不变。

- [PostgreSQL 18 全文检索](https://www.postgresql.org/docs/18/textsearch-controls.html)说明词干化、停用词、查询 AND/OR 与内置排名。本实验选择明确 OR 规则，避免整句隐含 AND；OR 也会引入泛词噪声，实际结果没有改善目标。
- [pgvector 混合检索](https://github.com/pgvector/pgvector#hybrid-search)和 [Supabase RRF 实现](https://supabase.com/docs/guides/ai/hybrid-search)提供维护中的实现依据，不直接证明本项目收益。利用现有数据库可减少依赖和迁移，但增加查询与融合维护成本；本日验证后决定保留现有实现。
- [pgvector 更新记录](https://github.com/pgvector/pgvector/blob/master/CHANGELOG.md)中 0.8.7 已发布、0.9.0 未发布；[Ollama 发布页](https://github.com/ollama/ollama/releases)已有更新稳定版，但缺少解决本漏检的项目证据。本日保留版本使比较可解释。
- [上下文增强检索原始实验](https://www.anthropic.com/engineering/contextual-retrieval)提出其他方向，但需要额外预处理和评测。新重排器、上下文增强、向量库迁移暂缓，不在一天中同时改变模型、分块和检索。

本次没有发现需要立即替换技术栈的明确收益；标准方案的存在与本项目的有效性是两件事。

## 10. 如果由你独立开发，应怎样做

1. **先定义正确行为。** 明确注册编号和注册平台这两个要求，确认物理页码与来源版本。AI 可以起草，但你必须核对原页。
2. **先定位再修改。** 沿 PDF、片段、向量、过滤、排序、装载逐层举证，不凭回答错误猜故障位置。
3. **把契约写清楚。** 先写输入、输出、条件、预算、失败码和验收，再实现。不要把“有引用”“HTTP 200”或 SUCCEEDED 当答案正确。
4. **一次改变一个因素。** 固定语料、模型、分块、最终五条、查询向量及参数。开发集上的一次失败是有用结论，不是继续无限试验的理由。
5. **理解 Python 数据处理。** 会用字典去重/聚合、列表排序、集合校验、contextmanager 和 finally 释放资源；能解释稳定顺序，避免依赖碰巧的迭代顺序。
6. **理解 SQL 与安全。** 用参数化表达式；每条候选路径都带授权和条件。输入转 tsquery 不等于 SQL 字符串拼接。新路径也不能省去版本和 READY 检查。
7. **理解事务和外部 I/O。** 模型等待期间不持有数据库事务，返回后重查条件，避免把过时证据当当前证据。
8. **理解预算持久化。** 请求前计费、重试也计费、写失败先阻断请求、全局计数不能因新对象重置。锁和文件保护防误用，不等于抵御有本地写权限者的全面篡改。
9. **理解评测层次。** 来源召回不等于证据召回，证据召回不等于进入上下文，进入上下文不等于选句正确，选句原文真实不等于回答完整。
10. **审查测试的证明范围。** 正确的假向量能验证 SQL，不能证明真实 Embedding 排名。真实模型需要独立原页语义复核。每次行为改变或 bug 修复都要有对应回归测试。
11. **审查 AI 产物。** 检查正确性、错误处理、测试、安全、可维护性。要求 AI 给证据和负面结果，不能只看“已完成”或测试总数。
12. **交付可复现材料。** 记录版本、输入哈希、调用次数、实际退出码、待办与保留策略。先检查提交列表，排除缓存、凭据及别人的改动，再提交、推送并验证远端。
