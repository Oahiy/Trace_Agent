## 3. 为什么选择这十份资料

保留 PRISMA 2009、PRISMA 2020 和 2009 Explanation and Elaboration 三份原资料。补充 Abstracts 2013、Equity 2012、2013 胃肠/肝病学期刊 endorsement 研究、2016 生物医学报告研究、2015 ENT 报告研究、2018 流程图研究及 2023 牙科报告研究。主题仍为系统综述的报告规范、研究方法和报告质量，不扩展到治疗建议或第三场景。

新增七份均从 PLOS 官方出版页面与 PDF 下载入口取得，使用七个不同 DOI，没有把镜像或清单附件计作独立论文。来源、作者、年份、许可依据与定位都在清单中。

两个实际纠错例子：牙科文章发表于 2023-12-14，不能由早期候选文件名推断为 2024；Abstracts 2013 首页和出版页面明确采用 CC0，不能一概写成 CC BY。其他资料逐篇记录 Attribution 声明；未明确版本的许可不推断具体版本。仓库仅提交元数据和必要的短锚点，不提交下载 PDF、出版 HTML、提取全文或页面预览。

目前所有来源都来自同一出版社，这是可访问性、明确许可和既有安全下载器兼容性之间的取舍，不代表文献全面性或医学知识覆盖。最初候选的 BMJ 解释论文等没有被假称为已下载核验。十份资料均符合现有 5 MiB、50 页、20 万字符上限，没有放松限制迁就资料。

## 4. 输入、输出与执行路径

输入是受版本控制的三个 JSON 文件与已锁定 PDF。输出是安全的检查报告；prepare 另外输出 `.cache/day8/snapshot-<标识>.json`，包含来源 ID、文件哈希、解析规格和片段文本、ordinal、物理页或字符定位。

执行顺序：

1. 限制元数据文件大小，读取 UTF-8 JSON，拒绝重复键。
2. Pydantic 使用 strict、extra=forbid，拒绝 bool 年份、未知字段、空字段、非法路径或来源。
3. 检查 DOI、来源 ID、文件哈希和缓存引用唯一；检查发表日期与年份一致。
4. 检查三十题的唯一 ID、规范化问题重复、分类和 10/20 分组；核对来源范围、证据与预期来源、年份过滤及身份夹具。
5. 对规范化 JSON 计算 SHA-256，核对 corpus、评测和锁文件关联。字段内容变化必须显式形成新版本；不能静默重写锁来接受漂移。
6. 检查缓存路径解析后仍处于项目内的 `.cache/`，并检查文件大小及原始字节哈希。
7. 使用现有子进程解析器和 `ingest-v1`，核对 pypdf 6.20.1、1000 字符切分、100 字符重叠、页数及字符数。
8. 核对每个锚点在指定物理页和至少一个片段内存在。空白与大小写规范化只用于比较，不修改保存文本或字符偏移。
9. prepare 将确定性内容写入同目录临时文件，flush/fsync 后以不覆盖方式发布；相同内容重用已有文件，不同内容明确冲突。finally 删除临时文件。

SHA-256 在这里负责识别内容和检测漂移，不证明真实性、许可或结论正确性，也不是抵御有写权限者同时改清单和锁的签名机制。字段顺序不影响规范化哈希，列表顺序仍属于版本内容。

### 下载、截止与失败

`check` 完全离线；只有 `prepare --download` 会恢复缺失文件。复用现有下载器，仅允许 HTTPS 的 `journals.plos.org`，不使用环境代理、不携带身份信息、不自动跟随跳转、不自动重试。网络阶段超时 20 秒，总截止 30 秒，流式下载最多 5 MiB；字节哈希吻合后才发布文件。

已有文件损坏时明确失败，`--download` 不覆盖它。来源缺失、大小不符、哈希不符、解析规格漂移、页数/字符数变化、页内锚点缺失、片段锚点缺失及快照冲突都有不同的安全错误码。解析异常、JSON/Pydantic 错误和意外异常分别映射固定错误，不输出原始异常、原文、路径、SQL 或凭据。

解析继续使用默认 60 秒截止且不自动重试；超时会 kill 并回收子进程。macOS 上地址空间硬限制仍未启用，不把这些公开资料检查表述为生产恶意文件隔离证明。30 秒下载截止不是十份资料的总任务截止；离线命令目前没有断点续跑数据库任务的语义。

## 5. 三十条评测究竟证明什么

| 类别 | 开发 | 验收 | 合计 |
|---|---:|---:|---:|
| 单文档 | 4 | 8 | 12 |
| 跨文档 | 2 | 4 | 6 |
| 无答案 | 2 | 4 | 6 |
| 冲突处理候选 | 1 | 2 | 3 |
| 注入或越权 | 1 | 2 | 3 |

全部十份来源都至少在一个题目的证据中使用。每条有英文问题、查询来源和可选年份、预期行为、来源与页内锚点、必须保留的结论及限制。`review_basis` 描述的是 Codex 核对，不是开发者签名或模型评测结果。

来源 ID 是可移植标识，不是公开 API 的 document UUID。普通题使用 owner_a 夹具；越权题显式使用 owner_b 访问 owner_a 的资料，预期沿用 404 resource_not_found。只有完成实际注册后才能在隔离集成测试中建立 source_id → document UUID 映射，不能让模型或客户端提供 owner 来改变权限。

注入题是合成恶意用户请求，真实原文没有被修改，也没有伪造医学文献。它们不证明文档内间接注入已被防御。诊断、处方、剂量和治疗推荐的完整自动化安全测试仍需在未来研究输出实现时补齐，不能用三道安全题或既有上传权限测试替代。

六条无答案根据明确的来源范围、年代或过滤空集标注，不能以模型是否愿意回答决定真值。claim、证据位置和限制也不能只靠精确字面匹配确认含义。验收集当前仅作为固定回归集：工程校验会读取其结构与引用，不能反复用它调 Prompt 再宣称是盲测；近似题和相同来源复用仍限制独立性，三十题不构成大型统计样本。

当前没有运行生成模型、Embedding、检索或研究端点，所以没有 Recall、MRR、回答支持率、延迟、Token 或模型费用成绩。后续来源级 Recall@5 的分母为有预期来源的检索题，不能混用片段数；MRR 使用首个相关来源对应结果的排名。引用 ID 与位置合法、结论受原文支持、资料有答案时有效回答、无答案时正确拒答需要分别检查。全部拒答不能得到有效回答高分。

## 9. 如果由你独立开发

先从一份文件、一题、一段证据做起。先手写预期，再让 AI 帮忙实现校验；不要根据 AI 已写出的代码反推测试。理解函数的输入输出后，主动改变哈希、页码、年份、来源范围和已有准备文件，观察失败是否符合需求。随后扩展到三份/三题，再扩大数据。

你应能说明三层不同保证：Pydantic 保证字段和关联规则；文件/页/片段校验保证指定字节与定位存在；语义复核保证结论、条件和限制确实受到支持。前两层通过不能代替第三层。

开发时尤其注意：

- 公开 API UUID、来源 ID、文件哈希、切分 ordinal 不是同一种身份；不要拿它们互相替代。
- 网络 I/O、解析和数据库事务边界要明确。后续接数据库时，耗时解析/模型等待不应持有 SQL 事务，完成前再次校验执行权。
- 幂等不是“文件存在就跳过”。必须核对内容；相同输入应重用，不同结果应失败或产生明确新版本。
- 读取数据的路径和自动下载的域名都要限制；不要为方便扩展为任意路径/URL。
- 证据比较可以忽略空白，保存与定位不能随意规范化，否则 TXT 偏移或历史片段会失效。
- 阅读完整相关段落、表头、脚注和日期。引用了正确页码仍可能把观察关联写成因果、把年份混淆、忽略样本差异。
- 不要自动修复坏文件、重写锁、降低配额或删除失败用例来取得绿色结果。
- 检查真实 diff 和实际报告，再提交明确文件；不要带上凭据、缓存、原始全文或用户无关改动。

今天对应 AI Coding 的需求分析、任务分解与协作、审查、调试、测试设计和可复现交付；对应实习能力以 Python 后端数据校验、幂等、RAG 评价和安全边界为主。它是应用工程训练，不是模型训练或算法研究。AI 可以整理候选来源、起草标注、实现校验并运行测试；你必须独立确认语义与许可、审查代码和测试，并解释实际运行边界。这些是准备重点，不保证某家公司会考这些具体题目。
